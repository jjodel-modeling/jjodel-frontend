# Proposal: the simulator's UI and its state data (2026-10-02)

Status: **design accepted by Alfonso on 2026-10-02** («mi convince»), to be written into `docs/decisions.md` by the simulator's owner chat. Numbers below are provisional (`R-SIM-P1..P8`): the owner chat assigns the real ones after the last R-SIM on its branches (the trunk is at R-SIM-101 on 2026-10-02; R-SIM-98 was reserved once, so check the branches before numbering).

Design reference: the canvas «Simulator UI and state data» (Claude Design, six artboards: M2 panel, M2 state attributes editor, M1 compact panel, M1 run inspector, canvas, notation). Every artboard uses an invented Turnstile model (Locked, Unlocked, Alarm; `model.[coins]`, `model.[passes]`, `model.[balance]`, input `model.[amount]`, `self.[visits]` on State, `node.[heat]` on State, `node.[count]` on Transition). The mock-up is the reference for layout and vocabulary, not for pixel values: the lanes measure against the trunk.

Evidence for the problem, read on the trunk at `9e6adf7` (2026-10-02): the run's σ reaches the user only as one clamped line (`markingLine`, `simBridge.ts:829`, `Marking: … · count = 3` inside the 262 px panel) and as the `attr = value` card under a node (`SimNodeRunState.tsx`, semantic only). The presentation state is computed (`state.presentation`, `derived.presentation`, `netCompile.ts:546`, `derivedEvaluator.ts:548`) and shown nowhere: `simRunState.ts` exports no reader for it, and no viewpoint can read it.

## The rows

- **R-SIM-P1** (2026-10-02, accepted by Alfonso 2026-10-02, evidence: read, verified: none, reversible: branch).
  **Two spaces, one visual key, nuXmv names.** The abstract (semantic) state σ and the concrete (presentation) state `node` are always shown apart and never mixed in one list. σ is drawn solid slate, with the glyph `σ`; `node` is drawn in the viewpoint colour of the design system (pink, `#db2777` family, dashed outline), because presentation state belongs to the view. The kind of an attribute is named as in nuXmv everywhere it shows: `VAR` (stored), `DEFINE` (derived, name in italics, never assigned), `IVAR` (input, asked at the press that reads it). A value changed by the last step is tinted with the run's cyan and shows `before → after`. Notation artboard is normative for these states: unchanged, changed now, past step, input asked, out of domain, undeclared.

- **R-SIM-P2** (2026-10-02, accepted by Alfonso 2026-10-02, evidence: read, verified: none, reversible: branch).
  **The roles dialog's «Data» page becomes «State», in two columns. Amends the label of R-SIM-71 and R-SIM-81(3).** «Data» collides with the Data Manager (R-DMV-1) and does not say that these are run state. The page shows the abstract column (globals `model`, then one group per metaclass) and the concrete column (one group per metaclass), with an arrow between them reading «σ is read one way»: a presentation equation may read σ, a semantic one that reads `node` is E-NODE, flagged on its row before Apply (the check `derivedEvaluator.ts` already makes, moved before Apply). A row's columns: name, kind chip, domain, initial or equation, access path (`model.[x]`, `self.[x]`, `node.[x]`). The selected row opens «Written by» (the actions and entries that assign it) and «Read by» (guards, actions, equations, and for a concrete row the view that draws it, when P7 lands). Below the columns, a read-only «Export preview» renders the abstract declarations in `.smv` syntax. It is a rendering of the declarations, not the exporter (spec step 4–5 stays deferred); if the owner chat judges it too close to the deferred `.smv` generation, it leaves the lane and the rest stands. The model's own `Data…` dialog (R-SIM-94) takes the same table with the metaclass fixed to Global and is renamed «State…».

- **R-SIM-P3** (2026-10-02, accepted by Alfonso 2026-10-02, evidence: read, verified: none, reversible: branch).
  **The compact M1 panel shows state, not a line. Amends R-SIM-82 (the marking line) and R-SIM-92 (the Output line, which becomes a Watch row).** Above the transport row, in this order from the top: «Watch» (up to four pinned attributes, globals first by default, each with value, a domain bar for a range, a chip for `DEFINE` or `IVAR`, the delta when changed), «Marking» (one chip per marked place, `×n` from two tokens), «Events» (one button per event, the reason in the title when off, an `amount?` chip when the press asks an input). The transport row (Reset, Step, Play, Stop) and the Choices control stay where R-SIM-65, R-SIM-66 and R-SIM-101 put them: the panel still grows upward and the buttons never move. The status block under them carries the pill, `step n`, the seed, and the last step in one line (`#7 reset · t5 Alarm → Locked · visits 2→3`). Pins are a viewer preference kept beside the run policy in `simRunState.ts`, outside Redux and never in a bag (R-SIM-6 holds; a pin does not move `runSignature`).

- **R-SIM-P4** (2026-10-02, accepted by Alfonso 2026-10-02, evidence: read, verified: none, reversible: branch).
  **A run inspector, opened from the panel.** An expand button on the panel opens the inspector: the whole σ (globals with domain bars, then per metaclass per instance, the marked ones flagged), the concrete state in its own pink section (one chip per element and attribute), and the trace. Where it docks (an rc-dock tab beside the editor, or the right rail) is a question for the lane's discovery; the compact panel stays the default and the demo path.

- **R-SIM-P5** (2026-10-02, accepted by Alfonso 2026-10-02, evidence: read, verified: none, reversible: branch).
  **The trace is navigable: configurations are kept. Extends R-SIM-100.** `SimRun` keeps the committed configurations beside `trace`, capped at the last 1000; older ones are rebuilt by replay from the seed and the trace when asked. Choosing a step in the inspector shows σ, `node` and the canvas overlay as they were, under a banner «Viewing step n. The run is still at step m» with «Back to live». Viewing is read-only: an input pressed while a past step is shown acts on the live configuration and returns the view to live. Nothing of this is persisted.

- **R-SIM-P6** (2026-10-02, accepted by Alfonso 2026-10-02, evidence: read, verified: none, reversible: branch).
  **The σ overlay on the canvas is opt-in per attribute. Amends the σ card of S15 slice A1.** The overlay stays the simulator's own (R-SIM-3 pattern, the same on every viewpoint): token, enabled transitions dashed in cyan, the marked node's border. The `attr = value` card under every node is replaced by tags shown only for the attributes the viewer turns on (default: none, except the attributes that changed in the last step, shown for that step only). Globals can be shown in one card pinned to the canvas corner. Both are viewer preferences beside the pins of P3.

- **R-SIM-P7** (2026-10-02, accepted in substance by Alfonso 2026-10-02, evidence: read, verified: none, reversible: branch). **Needs Alfonso's explicit ratification in the owner chat: it amends R-SIM-4.**
  **`node.[x]` reaches the viewpoints, read-only.** The concrete state exists so that a notation can draw the run; today no view can read it. The run-state singleton exports a reader of an element's presentation (stored then derived, as `netStep.ts` resolves it), and the IR interpreter exposes it to view expressions with the same syntax as the engine, `node.[x]`, absent when no run knows the element (a view gives its own default). This adds a dependency to the interpreter that R-SIM-4 kept out, so the lane opens with a discovery and a Layer Impact Report: how a view expression reads it, how the view re-renders on the `'mark'` version without re-rendering the whole canvas, and what a derived viewpoint (`ir.generated`) does with it. Views never write it (R-SIM-6 and R-SIM-18 unchanged).

- **R-SIM-P8** (2026-10-02, accepted by Alfonso 2026-10-02, evidence: read, verified: none, reversible: branch).
  **An «Inspect node.[x]» switch on the canvas.** Off, the viewpoint shows only its drawing. On, every element that has presentation state carries dashed pink tags naming each value (`heat 3`, `count 2`), so a user can tell the data from the notation. A viewer preference, off by default. It depends on P7 for the drawing and works without it for the tags.

## Lanes, as this proposal sees them

Four lanes, the first three on disjoint file sets and parallel: L1 the «State» page and the model dialog (`SimRolesModal.tsx`, `SimDataModal.tsx` and their SCSS); L2 the compact panel, the inspector and the trace (`SimulationPanel.tsx`, `simRunState.ts`, `simBridge.ts`, a new inspector component, `simulation-panel.scss`); L3 the canvas overlay (`SimNodeRunState.tsx`, `simCanvasState.ts`, `simNodeRunState.scss`); L4 discovery for P7 and P8, read-only, then its own Phase 2 after Alfonso ratifies the amendment of R-SIM-4. Each lane writes its discovery report in `docs/discovery/` with the standard naming.

## Open for the lanes' discoveries

Where the inspector docks (P4). Whether the Export preview stays (P2). How a view expression reads `node.[x]` and re-renders (P7). Whether «Read by» for a concrete row can name the view before P7 lands, or shows only equations until then.
