Jjodel · documento vivo

Storia dello sviluppo

Da un prototipo Create-React-App del marzo 2021 a una piattaforma di metamodeling web con tre linguaggi, authoring visuale della sintassi concreta e un redesign UI in corso. Feature, requisiti, obiettivi e milestone, ricostruiti da git e dal knowledge base di progetto.

Ultimo aggiornamento: 2026-08-01 · fonti: git history (2.314 commit), mappa sintassi concreta, contesto di progetto, file sessione

01Visione e obiettivi

Perché Jjodel esiste, e i principi che ne hanno guidato ogni era.

Metamodeling senza attrito

Portare l'MDE nel browser: niente toolchain desktop, niente rigenerazioni. Metamodelli e modelli co-evolvono live, per ricercatori, educatori e studenti dal principiante all'esperto.

Riflessività

Un nucleo dati riflessivo (DState, proxy D/L) in cui ogni cosa, dal metamodello alla vista, è un modello manipolabile a runtime.

Sintassi concrete come dati

La notazione grafica non è codice: è un IR tipizzato, persistito e autorabile da UI. Espressività e robustezza insieme, con jsxString come livello di uscita.

Ridurre il cognitive load

L'obiettivo cardine del redesign 2026: progressive disclosure (Basic/Advanced), pannelli flottanti, un design system coerente. Piena funzionalità, metà del rumore.

05Requisiti

Funzionali

Soddisfatti

  • Metamodeling riflessivo con propagazione live M2↔M1
  • Più viewpoint e viste sulla stessa astrazione
  • Authoring visuale della notazione (nodi, righe, edge E-ref)
  • Trasformazioni, espressioni e scripting in-tool
  • Collaborazione, multi-progetto, assistenza AI

Parziali

  • Edge authoring: manca object-as-edge (E-obj)
  • Righe: editing inline e Operation con parametri
  • Routing edge configurabile (oggi Manhattan fisso)
  • Disclosure estesa a tutti i pannelli (oggi vertex)

Aperti / bug

  • bug Rehydration viewpoint IR al reload (blocca il dogfooding)
  • Rename metaclasse non invalida i path (no-match silenzioso)
  • Decorative views, rules editor, reattività cross-object
  • Dual-canvas (due modelli affiancati)

Non funzionali

Perseguiti attivamente

  • Cognitive load ridotto: progressive disclosure, pannelli on-demand
  • Coerenza visiva: design token slate/cyan, zero layout shift
  • Robustezza evolutiva: typecheck a baseline Δ0, two-phase con discovery report, hard stop visivi
  • Tracciabilità: log dei task, documenti vivi (mappa copertura, contesto), checkpoint di sessione

Da misurare o consolidare

  • Performance su modelli grandi (mai misurata sistematicamente)
  • Copertura test sulla UI (aree pannelli senza test)
  • Accessibilità e internazionalizzazione
  • Onboarding: docs e video pills in evoluzione

06Come lavoriamo

Dal giugno 2026 lo sviluppo segue un modello a tre attori: Alfonso decide architettura e design e fa ogni verifica visiva; la chat di progetto co-progetta, analizza e genera prompt autocontenuti; Claude Code esegue chirurgicamente col minimo cambiamento. Le discipline: two-phase (discovery read-only con report salvato, hard stop, poi implementazione), un commit per volta con verifica visiva, replica HTML approvata prima di ogni skin, e un knowledge base che fa da memoria: mappe di copertura, ratifiche, file di sessione.
