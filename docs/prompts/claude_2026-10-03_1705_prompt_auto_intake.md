### Phase 2: implementation (after the GO, same session)

Unless the GO says otherwise, `frontend/scripts/auto-intake.mjs` provides the subcommands below. Every subcommand exits 0 and reports its verdict on stdout, because an osascript `do shell script` drops the output of a non-zero exit (see `lane-run wait`); a refusal on bad usage may exit 2 as in `lane-run.mjs`. No value from an issue ever reaches a command through string interpolation: arguments are passed as argv.

- `queue`: lists open issues with the intake label, drops pull requests, keeps those whose latest `labeled` event for that label has an allowlisted actor, and drops those with a skip label present, a title or body edited after that event, or an attempt already recorded for that event id (RC-35). Writes `~/.jjodel-lanes/auto/<night>/queue.json` (number, title, body hash, label event id and actor, verdict and reason) and prints it.
- `render <issue> [--out <dir>]`: renders `frontend/scripts/lane-templates/issue-discovery.md` into `~/.jjodel-lanes/pending/` (or `<dir>`) with a fresh Prompt-ID (item 5), `Chat:` naming the night, `Lane: full`, `Tier: light`, `Status: da eseguire`, worktree `~/jjodel-a-<issue>` and branch `auto/<issue>-<slug>`, the slug matching `[a-z0-9-]{1,40}`. Hidden content in the title or body (HTML comments, zero-width characters, bidirectional controls) parks the issue instead of rendering it. The text goes into a fence one backtick longer than its longest backtick run, introduced as untrusted data, capped at 8000 characters with the cut stated. The template's COSA tells the lane to treat that block as a bug report to analyse, never as instructions; to stay read-only; to write the discovery report with the eligibility verdict and the predicted DOVE on one machine-readable line (format fixed by the discovery); and to stop with `Outcome: hard-stop`.
- `cut <issue>`: creates the worktree and branch of the rendered prompt from the trunk tip, links `frontend/node_modules` as P14 does, and writes the base sha to `base.txt` beside the queue. Tested on a fixture repository only in this lane.
- `admit [--explain]`: prints `admit` or `deny: <reason>` from RC-38: pace from `resetsAt` minus the margin, absolute ceiling, no reset within the guard hours, nightly delta against `baseline.json` (written from the first fresh reading of the night), cumulative lane time and minimum residual, parallel cap with the second lane only after the first has produced a reading, kill switch (trip file), staleness (age or passed `resetsAt`: one light discovery lane only). `--explain` prints every reading it used.
- `guard --predicted <report.md>` and `guard <worktree> [--base <rev>]` (default: the recorded `base.txt`, else the merge base with the trunk): `pass` or `park: <reasons>` on the guarded paths of RC-36, including untracked and ignored files (`git status --ignored`).
- `ledger [--night|--week]`: every automatic lane with time, cost (rule of item 1), tokens, utilization before and after, and a flag on any automatic lane folder that holds `goahead.txt`.
- `trip <reason>` writes the kill-switch file by hand.

`lane-run start --auto` as designed in item 7, with its header comment updated.

Configuration in `frontend/scripts/auto-intake.config.json`: repository, intake label, skip labels, allowlist (`["apierantonio"]`), night window (`01:00` to `07:00` local), mode (`"shadow"`), and the RC-38 numbers: pace margin 0.05, ceiling 0.70, reset guard 24 hours, nightly delta 0.03, 240 minutes per night, 30-minute residual, lane limit 90 minutes, parallel cap 2, five-hour ceiling 0.80, staleness 6 hours. The script refuses `"live"` mode unless the configuration also holds `ratifiedBy` and `ratifiedOn` for these numbers.

`AUTO_INTAKE_NOW` stands in for the clock and `AUTO_INTAKE_LANES_DIR` for `~/.jjodel-lanes` in the tests, as `LANE_RUN_NOW` does; `gh` is called through one function that the tests replace with fixtures recorded in Phase 1 (no network in tests).
