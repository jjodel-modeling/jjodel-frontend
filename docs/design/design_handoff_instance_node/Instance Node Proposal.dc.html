Turno 4 · Istanze singleton

Il singleton è una pill, non un rettangolo

Un'istanza con view.singleton = true è un valore atomico: identità e tipo coincidono e non c'è compartment da mostrare. Riceve la stessa forma dei value renderer del livello 3 — pill, radius full, superficie bianca, bordo hairline slate — così che Blue dentro la riga color e Blue come nodo su canvas siano la stessa cosa.

Etichetta: se la metaclasse ha una superclasse astratta la pill legge Color : Red — la superclasse è l'unica informazione non ridondante, perché dice a quale insieme chiuso il literal appartiene. Senza superclasse astratta, solo il nome: Config : Config è rumore, Config basta.

Superclasse a peso secondario, nome sottolineato: la convenzione UML resta sul nome dell'istanza.
4b Senza superclasse astratta

Sopra a riposo, sotto selezionato. Il ciano resta libero per la selezione, come in 3b.

color Color:Blue cfg Config
Color:Blue Config
Stessa forma nelle due posizioni: solo scala e sottolineatura cambiano — la riga è inline, il nodo è un'istanza.
4d Singleton con struttura
1 Config
debug true level 2
Se il singleton ha slot valorizzati la pill non basta: torna rettangolo, e il badge 1 porta l'informazione di cardinalità.
Regola per l'IR

Il label del singleton si risolve così: se esiste una superclasse diretta astratta → «Super : Nome»; altrimenti → «Nome». Con più superclassi astratte si prende la prima dichiarata e le altre restano nell'inspector. La forma si risolve sul contenuto, non sul flag: singleton && slot valorizzati === 0 → pill; altrimenti rettangolo con badge 1. Nessun fill colorato in nessuno dei due casi.

Turno 3 · Default e derivati

2c come default, 2b e 2d riportati sul neutro

Dato 2c come base, il colore categoriale non è più il modo primario per dichiarare il tipo — quindi 2b e 2d vanno rifatti in chiave slate, con la tinta come override esplicito e non come default. Tutti mostrano lo stesso compartment.
