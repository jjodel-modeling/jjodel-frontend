## Info strutturali scoperte

- Il manager legge dall'indice IR di un viewpoint esplicito: `computeIRSignature(state, viewpointId?)`,
  `getIRIndex(state, sig, viewpointId?)`, `useIRFormView(objectId, viewpointId?)`; `IRForm.tsx` legge il
  tema dal singleton per `host === 'manager'`.
- `resolveTableSpec` (`viewpoint/ir/tableViews.ts`): solo view senza predicato, ordine di `resolveIRView`.
- Una `vertex` ir senza `shape` fa saltare `compileView` (`irCompile.ts:305`) e azzera l'indice.
- `DViewElement.new2` vuole il padre come oggetto: una stringa cade in silenzio su `Pointer_ViewPointDefault`.
- `selectors.ts:552-559` applica come decorative le view dei viewpoint non attivi e non esclusivi:
  il singleton deve restare `isExclusiveView: true`.
- Node 18 (nvm) fa fallire `vite build` (`crypto.hash`); usare Node 23 di Homebrew.
- La VM del bridge lascia `index.lock`/`HEAD.lock`/`maintenance.lock`/`tmp_obj_*` a ogni comando git
  che tocca l'indice; da lì solo letture (`git log`, `git show`); commit dalla shell nativa del Mac.
- Il pannello IR Source (scheda Source) mostra l'IR salvato; via console `LPointerTargetable.fromPointer(id).ir = {...}`
  scrive l'IR (stesso `set_ir` dell'authoring); `store.getState()` è globale.
