## 3. The binding
- **Storage.** Flat keys in the derived `DViewPoint`'s `_state`, written in `newVP`'s callback before persist (the channel `viewpointType` uses, `utils/deriveViewpoint.ts:55-59`): `derivedFrom`, `derivedNotation`, and one `derivedRole_<classId>` per class. - **The dialog.** Mounted in `App.tsx` and opened by an event from `events/registry.ts`, as `ValidationRulesModal` is. It has a notation select (default Generic) and a metaclass → role table. Prefill: `bindProfile(profile, sketchOfMetamodel(lookup, mm), bag)` (`profileBinder.ts:387`), with the stored binding as `bag` (kept, `:398-399`), inverted per class. The profile is `stateMachine` for Statechart and Automaton, `petri` for both Petri notations, `flowchart` for ISO and BPMN.
- **ER and UML signals, in a new pure module.** An entity holds a composition to a class with `type`. A relationship is a two-reference class or matches `/relat/`. A key matches `/key|id|primary/`, a cardinality `/card|mult/`. A UML class holds `/attr|propert/` and `/op|method/`. Associations and generalizations are two-reference classes, told apart by `/general|inherit/`. Regeneration: question 4.
