Four presets, three switches

Unified rail — tree fixed, no tabs, no Recent. The safe default for teachers and first sessions.
1b
Inspector first — tabs on. Best on short screens and laptops.
2a
Adaptive rail — collapsible tree. The recommended default.

Adaptive + Recent — adds the recency list. For tall monitors and long editing sessions.
The gate does the work
In Basic the setting does not exist — no gear, no picker, one layout. A preference only helps people who already know what they want, and by definition that is the Advanced population. Switching back to Basic renders 2a but keeps the stored preset for their return.
Turn 3 · Tall screens

Recent, only where there is room

Yes — with two conditions. It has to be real navigation history, not a second tree, and it must vanish the moment the rail is short, otherwise it steals the space the inspector needs. Here it is the top zone of 2a: collapsed to a 30px header below ~900px of rail height, capped at five entries, gone entirely in Focus posture. Click a row — the tree does not move, only the inspector does.

Rules that keep it useful
Five entries, never more
Recency lists stop being scannable past five. Older jumps belong to the filter, not to a list.
Visited, not favourite
Ordered by last visit and deduplicated, so it mirrors what the user just did instead of asking them to curate anything.
Every row carries its context
Letter badge, name, owning classifier, age. Without the owner, name appearing three times is noise.
First to go when space is tight
Below ~900px of rail height it renders collapsed; in Focus posture it is not rendered at all. It may never push the inspector below the fold.
Jumping is not scrolling
Clicking a recent item moves the inspector and the tree selection, but does not re-scroll the tree — the user's place in the structure survives the detour.
The one risk
A third list in a 400px rail can read as "three trees". It works here only because Recent is flat, short, and typographically quieter than the tree. If it ever grows headers or nesting, cut it.

How the two postures merge
One panel, not two modes to learn
Header, inspector and footer never move. Only the tree pane collapses, so the switch reads as a change of height — not a change of screen.
Three ways in, all reversible
Double-click the header (your idea, kept), the labelled Focus / Browse button beside it, or simply pick a leaf in the tree. ⎋ always returns to Browse.
The inspector earns the space it gets
In Browse the identity block is 22px and flags are compact chips; in Focus the badge and title scale up and flags become labelled switches with hints. Same data, density matched to the room available.
Caveat worth testing
Double-click on a header is invisible to a first-time user, so it stays a shortcut for experts — the explicit button carries discovery. Never make it the only way in.

J / K to step
  • Tree and inspector never compete: picking an element hands the whole panel to the inspector, and the breadcrumb chip walks back.
  • The selected element gets a real identity block — badge, name, kind, signature — so the user always knows what they are editing.

  • J / K step through siblings without going back to the tree — the fastest path for bulk edits.
  • Costs a click when hopping between elements; wins when editing deeply.
