## 3. INVENTARIO MODEL LAYER

### joiner/ (Core Data Layer)

| File | Classe/Interfaccia | Responsabilità | Note |
|------|-------------------|----------------|------|
| `classes.ts` | D*/L* hierarchy | Definisce tutte le classi runtime (DModel, LModel, DClass, LClass, DObject, LObject, ecc.) | Usa `@RuntimeAccessible`, proxy, LPointerTargetable |
| `proxy.ts` | TargetableProxyHandler, MyProxyHandler, MapProxyHandler | Gestione proxy per accesso trasparente D -> L layer | Core del sistema L-proxy |
| `types.ts` | Dictionary, GObject, Nullable, EdgeBendingMode | Tipi primitivi, enums, tipi generici | Fondamentale per tutto il codebase |
| `index.ts` | (re-exports) | Hub principale di export per model, view, redux | Importato da quasi tutti i file |
| `typeconverter.ts` | TypeConverter | Conversione tipi | Utility |
| `components.tsx` | (React exports) | Export componenti React del joiner | Bridge UI |
| `ExecuteOnRead.ts` | (init logic) | Inizializzazione eseguita all'import del joiner | Side effect on import |

### model/ (Model Implementations)

**Gerarchia classi principale:**

```
DPointerTargetable (abstract base)
├── DModelElement → LModelElement
│   ├── DNamedElement → LNamedElement
│   │   ├── DClassifier → LClassifier
│   │   │   ├── DClass → LClass          # Definizioni classe
│   │   │   └── DEnumerator → LEnumerator # Enumerazioni
│   │   ├── DStructuralFeature → LStructuralFeature
│   │   │   ├── DAttribute → LAttribute  # Attributi istanza
│   │   │   └── DReference → LReference  # Riferimenti
│   │   ├── DOperation → LOperation      # Operazioni
│   │   ├── DParameter → LParameter      # Parametri
│   │   ├── DPackage → LPackage          # Namespace
│   │   └── DEnumLiteral → LEnumLiteral  # Literal enum
│   └── DTypedElement → LTypedElement
├── DModel → LModel        # Root metamodel container
├── DObject → LObject      # Istanza M1
├── DValue → LValue        # Valore attributo/reference
├── DGraph → LGraph        # Container grafo
├── DVertex → LVertex      # Nodo grafo
├── DEdge → LEdge          # Arco grafo
└── DMap → LMap            # Dictionary container
```

**Pattern critici:**
- `DObject.new()` ritorna ID temporanei (non usabili per lookup Redux)
- `LPointerTargetable.fromD(id)` per ottenere proxy L da un ID
- `$attr.value = val` per scrivere via proxy
- `lModel.objects.find(o => o.name === name)` per trovare per nome

## 12. OSSERVAZIONI E RED FLAGS

### Architettura

1. **Build system ibrido:** `react-scripts` + `webpack-cli` coesistono con Vite 7.3.1 nelle dependencies. La migrazione a Vite non e completa -- react-scripts e webpack-cli andrebbero rimossi o spostati in devDependencies.

2. **jQuery in un codebase React:** `jquery` e `jqueryui` sono nelle dependencies ma con ~0 import rilevati. Probabilmente dead code residuo -- da rimuovere.

3. **Type safety compromessa:** 3,672 istanze di `any`/`as any`/`@ts-ignore` nonostante strict mode attivo. Concentrazione elevata in `joiner/` e `graph/` (core data layer). Rischio: bug silenziosi nei proxy e nella gestione stato.

4. **Dipendenze inutilizzate:** Almeno 5 dipendenze con 0 import (`react-itertools`, `jqueryui`, `nearley-unparse`, `path-data-polyfill`, `xml-formatter`). Gonfiano `node_modules` senza beneficio.

### Styling

5. **~600 inline styles:** Volume elevato di `style={{}}` nel JSX. Molti hardcodano colori e spacing che dovrebbero usare design tokens. Problema concentrato in `graph/`, `abstract/`, `Settings/`.

6. **50+ classi SCSS duplicate:** Stessi nomi (`.btn`, `.action-btn`, `.dock`, `.console`) definiti in file diversi senza scoping. Rischio: override involontari, comportamento imprevedibile.

7. **Naming convention misto:** kebab-case, BEM parziale, PascalCase e utility classes coesistono. Non c'e enforcement consistente.

8. **Legacy token migration incompleta:** 7 TODO nei file token che dicono "Remove after full migration". Le variabili legacy (`--bg-1`, `--bg-2`, `--gr-1`...`--gr-12`) coesistono con il nuovo sistema.

### Linguaggi

9. **JjScript senza test:** 60+ file, 19 comandi, ma 0 file di test. Unico dei 3 linguaggi (JjTL: 11 test, JjEL: 2 test) senza coverage.

10. **Event system non documentato:** 42+ eventi custom DOM senza schema o documentazione centralizzata. Accoppiamento implicito tra componenti tramite stringhe evento.

### Data Layer

11. **Proxy complexity:** Il sistema D*/L* con TargetableProxyHandler e un'astrazione potente ma fragile. La necessita di pattern come "deferred attribute setting" con `setTimeout(1000)` suggerisce problemi di timing nella propagazione stato Redux.

12. **ID temporanei DObject.new():** Pattern documentato in CLAUDE.md ma ancora fonte di bug. Richiede workaround (lookup per nome, non per ID).

### Performance

13. **Nessun code splitting evidente:** Un singolo bundle per 281K LOC. Con Vite 7.3.1 disponibile, lazy loading e dynamic imports potrebbero ridurre significativamente il tempo di caricamento iniziale.

14. **Double execution in StrictMode:** Bug aperto che causa doppia esecuzione dell'executor JjTL. Non critico in produzione (StrictMode disabilitato) ma impatta sviluppo.

### Rischi per UI Redesign

15. **Alto accoppiamento via eventi:** Cambiare struttura componenti (es. spostare Toolbar) richiede tracciare tutti i custom events che emette/ascolta. Non esiste un event registry.

16. **600 inline styles da migrare:** Un redesign CSS-first richiederebbe prima di estrarre gli inline styles in classi SCSS, altrimenti le modifiche al design system non si propagano.

17. **Settings components tutti stateful:** Tutti e 11 i componenti Settings usano useState. Potenziale per stato locale inconsistente tra sezioni.
